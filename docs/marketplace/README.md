# Marketplace แบบคีย์เอง (Shopee / Lazada)

โมดูลบันทึกการขายบนแพลตฟอร์มออนไลน์ด้วยการคีย์เอง ใช้โครงเดียวกันทุกช่องทาง
เพิ่มช่องทางใหม่ทำได้โดยเติม `SaleChannel` + config ใน `lib/marketplace/config.ts`

> โมดูล Shopee Open Platform (ดึงออเดอร์อัตโนมัติผ่าน API) อยู่ที่ [docs/shopee](../shopee/README.md)
> ทั้งสองโหมดใช้ **บัญชีพักเงินและการตั้งค่าเดียวกัน** จาก `MarketplaceChannelSetting`

## แนวคิดหลัก

ยอดขายทุกใบไม่ได้เข้าธนาคารทันที แต่พักไว้ใน **บัญชีพักเงิน** ของช่องทางก่อน
จนกว่าแพลตฟอร์มจะโอนจริง ทำให้:

```
ยอดคงเหลือบัญชีพักเงิน = เงินที่แพลตฟอร์มยังไม่โอนให้ร้าน (เสมอ)
```

## 3 flow

### 1. คีย์ขาย — `/admin/sales/{shopee|lazada}/new`

ใช้ `SaleForm` ตัวเดียวกับหน้าร้าน แต่ล็อกรูปแบบไว้:

| รายการ | ค่าที่ถูกล็อก |
|---|---|
| ประเภท | ขายสด (`CASH_SALE`) |
| การจัดส่ง | จัดส่ง (`DELIVERY`) |
| VAT | `NO_VAT` |
| ลูกค้า | ลูกค้าเริ่มต้นของช่องทาง |
| รับเงิน | 100% เข้าบัญชีพักเงินของช่องทาง |
| เลขที่เอกสาร | `SP{YYMM}####` / `LZ{YYMM}####` |
| เลขคำสั่งซื้อ | บังคับกรอก, unique ต่อ `[channel, channelRefNo]` |
| แก้ไข | **ไม่ได้** — ต้องยกเลิกแล้วคีย์ใหม่ |

**ยอดที่คีย์ = ยอดที่ลูกค้าจ่ายจริงทั้งใบ รวมค่าจัดส่งที่ลูกค้าจ่าย** (ใส่ในช่อง `shippingFee`)
เพื่อให้ยอดตรงกับ statement ของแพลตฟอร์ม — ค่าส่งที่ลูกค้าจ่ายถูกบันทึกเป็นรายได้
ใน FactProfit อยู่แล้ว ส่วนค่าส่งจริงที่แพลตฟอร์มหักจะเข้ามาเป็นค่าธรรมเนียมตอนกระทบยอด

### 2. คืนสินค้า — `/admin/sales/{slug}/returns/new`

เลือกใบขายก่อน แล้วเข้าฟอร์ม `CreditNoteForm` ที่ถูกล็อกไว้:
`type = RETURN`, `settlementType = CASH_REFUND`, คืนเงินออกจากบัญชีพักเงินของช่องทาง

รายการสินค้าถูกโหลดจากใบขายต้นทางมาให้ตั้งแต่ฝั่ง server — ผู้ใช้แก้จำนวน/ลบแถวที่ไม่ได้คืน
กลไกสต็อกและต้นทุนใช้ของ CN เดิมทุกอย่าง (`RETURN_IN` ด้วย avgCost ปัจจุบัน จึงไม่ทำให้ MAVG เพี้ยน)

**เคสคืนเงินโดยไม่มีสินค้ากลับมา** (refund only / ชดเชยลูกค้า / ค่าปรับ) **ไม่ออกใบลดหนี้** —
ให้ลงเป็นบรรทัด `PENALTY` ในรอบรับเงินแทน เพราะไม่มีของเข้าสต็อกให้บันทึก

### 3. รับเงิน — `/admin/sales/{slug}/settlements`

```
  ยอดขายที่เลือก        (ใบขาย, +)
− ยอดคืนที่เลือก        (ใบลดหนี้, −)
− ค่าธรรมเนียม          (บรรทัดที่กรอกยอดติดลบ)
+ รายรับพิเศษ           (บรรทัดปรับปรุงที่กรอกยอดบวก)
= ยอดที่ควรได้รับ        ต้องเท่ากับเงินเข้าจริง (ต่างเกิน 0.005 บันทึกไม่ได้)
```

กดยืนยันแล้วระบบสร้างใน transaction เดียว:

1. `Expense` — ค่าธรรมเนียมสุทธิ จ่ายออกจากบัญชีพัก ติด `channel` พร้อม `ExpenseCode` อัตโนมัติ (`SHP###` / `LZD###`)
2. `CashBankAdjustment` IN — เฉพาะเมื่อมีรายรับพิเศษ
3. `CashBankTransfer` — บัญชีพัก → ธนาคารจริง
4. `MarketplaceSettlement` + `MarketplaceSettlementLine` + `MarketplaceSettlementFee`

ยกเลิกรอบจะกลับรายการทั้ง 4 ชิ้น และปลด `activeSaleId`/`activeCreditNoteId`
ให้เอกสารกลับมาเลือกในรอบใหม่ได้

## กฎเรื่องกำไร (สำคัญที่สุด)

### ค่าธรรมเนียมรับรู้ที่ "วันขาย" ไม่ใช่วันเงินเข้า

`rebuildMarketplaceSettlementProfitFacts()` ปันค่าธรรมเนียมกลับไปยังใบขายแต่ละใบ
ตามสัดส่วนยอดขาย แล้วเขียน `FactProfit` ด้วย `businessDate = วันที่ขายของใบนั้น`

ขาย 30 ส.ค. แพลตฟอร์มโอน 5 ก.ย. → ค่าธรรมเนียมยังตกเป็นต้นทุนของเดือน ส.ค.
ไม่ทำให้กำไร ส.ค. พองและกำไร ก.ย. หดผิดปกติ

> **ห้ามเรียก `rebuildExpenseProfitFacts()` กับใบค่าธรรมเนียมของรอบรับเงิน**
> เพราะจะเขียนทับวันที่กลับไปเป็น `expenseDate` (= วันเงินเข้า) และการปันตามใบขายจะหายไป

ผลข้างเคียงที่ต้องรู้: งวดที่ยังมีออเดอร์ค้างรับเงินจะแสดงกำไร **สูงกว่าความจริงชั่วคราว**
รายงานผู้บริหารและหน้าประกาศแบ่งกำไรจึงขึ้นแบนเนอร์เตือนพร้อมประมาณการ
(ดู `estimatePendingChannelFees()`)

ถ้าประกาศแบ่งกำไรไปก่อนแล้วค่าธรรมเนียมมาทีหลัง ระบบแบ่งกำไรรองรับอยู่แล้ว —
ส่วนต่างจะโผล่เป็นยอดยกมาแบบ `RESTATED` ของงวดถัดไปผ่าน `computeCarryForward()`

### นิยามตัวเลข 3 ชั้น

```
ยอดขายสุทธิ  = Σ salesAmountExVat  (SALE + SALE_RETURN)
กำไรขั้นต้น   = Σ grossProfit       (SALE + SALE_RETURN)
เหลือจริง     = กำไรขั้นต้น − ค่าธรรมเนียมช่องทาง + รายรับพิเศษ
กำไรสุทธิทั้งร้าน = Σ เหลือจริงทุกช่องทาง − ค่าใช้จ่ายส่วนกลาง (Expense.channel = null)
```

**ห้ามเรียกตัวเลขระดับช่องทางว่า "กำไรสุทธิ"** — ค่าไฟ เงินเดือน ค่าน้ำมัน ฯลฯ
ไม่ได้ผูกกับช่องทางใดช่องทางหนึ่ง และจงใจไม่ปันส่วน เพราะไม่มีเกณฑ์ที่ถูกต้องจริง

### รายรับพิเศษ

รายการบวกจากแพลตฟอร์ม (subsidy ค่าส่ง / bonus / เงินชดเชย) บันทึกเป็น
`ProfitSourceType.OTHER_INCOME` — `netProfitAmount` เป็นบวก แต่ `salesAmount = 0`
เพื่อให้เข้ากำไรสุทธิเต็มจำนวนโดยไม่ไปเพิ่มฐานยอดขายจน %margin เพี้ยน

## เอกสารที่ถูกล็อก

`Expense` / `CashBankTransfer` / `CashBankAdjustment` ที่ถูกสร้างโดยรอบรับเงิน
และ `CreditNote` ที่ถูกกระทบยอดไปแล้ว **ยกเลิกตรง ๆ จากหน้าของตัวเองไม่ได้** —
`document-mutation-guard` จะบล็อกและบอกให้ไปยกเลิกที่รอบรับเงินแทน

ถ้าไม่มี guard นี้ ผู้ใช้จะยกเลิกใบค่าธรรมเนียมได้ ทั้งที่รอบยัง ACTIVE
ทำให้กำไรสูงเกินจริงและยอดบัญชีพักเงินหลุดจากความจริงพร้อมกัน

## ฟอร์มพิมพ์ — ใบเสร็จที่แนบไปในกล่อง

เอกสารนี้คือ **ใบเสร็จที่แนบไปในกล่องให้ลูกค้า ไม่ใช่ใบติดหน้ากล่องสำหรับขนส่ง**
คนอ่านคือผู้ซื้อ ทุกอย่างจึงเขียนคุยกับลูกค้า

ใช้ `SharedSalesDeliveryPrintDocument` ตัวเดียวกับหน้าร้าน แต่เมื่อ `sale.channel`
เป็นช่องทาง marketplace จะต่างจากใบหน้าร้านดังนี้:

| ส่วน | ใบ marketplace |
|---|---|
| หัวเอกสาร | "ใบเสร็จรับเงิน / ใบส่งสินค้า" |
| กล่องข้อมูลเอกสาร | เพิ่มแถวเลขคำสั่งซื้อของแพลตฟอร์ม, **ตัดแถวเงื่อนไขชำระและวันครบกำหนด** (ขายสดเสมอ) |
| ชื่อลูกค้า | ใช้ **ชื่อผู้ซื้อที่แอดมินคีย์** (`Sale.customerName`) มาก่อนลูกค้ากลางของช่องทาง — ถ้าเว้นว่างจะ fallback เป็นชื่อลูกค้ากลาง |
| ที่อยู่ | ใช้ **ที่อยู่ผู้ซื้อจากช่องที่อยู่ของใบขาย** (`Sale.shippingAddress`) ไม่ใช่ที่อยู่ของลูกค้ากลาง — และ **ซ่อนแถวนี้ทั้งแถว** ถ้าค่ายังเป็นข้อความตั้งต้นของช่องทาง |
| บล็อกการชำระเงิน | **ซ่อนทั้งก้อน** (เลขบัญชี / PromptPay QR / ตารางช่องทางรับเงิน) |
| แทนที่ด้วย | ข้อความขอบคุณ + ชวนติดต่อร้านโดยตรง + ช่องทางติดต่อ (โทร / LINE / เว็บไซต์) |
| ช่องลายเซ็น | **ตัดออกทั้งแถว** — ไม่มีใครเซ็นตอนแกะกล่อง |
| ยังคงไว้ | กล่อง "โปรดทราบ", QR ตรวจสอบเอกสาร, ลายน้ำต้นฉบับ/สำเนา, ตารางสินค้าและยอดรวมเหมือนหน้าร้าน |

ฟอร์มคีย์ขาย marketplace จึงมีช่อง **"ชื่อผู้ซื้อ" / "เบอร์โทรผู้ซื้อ" / "ที่อยู่ผู้ซื้อ"** ให้กรอก
(ใช้ฟิลด์ `customerName` / `customerPhone` / `shippingAddress` เดิมของ `Sale` ไม่ได้เพิ่มคอลัมน์ใหม่)
และซ่อนช่อง "เครดิต (วัน)" เพราะถูกล็อกเป็นขายสดอยู่แล้ว

ช่องที่อยู่เติมข้อความตั้งต้น "จัดส่งตามที่อยู่ในคำสั่งซื้อ {ช่องทาง}" ให้ก่อน
(เพราะที่อยู่จริงอยู่ในระบบของแพลตฟอร์ม และช่องนี้เป็นฟิลด์บังคับของการขายแบบจัดส่ง)
แอดมินพิมพ์ทับด้วยที่อยู่ผู้ซื้อจริงได้

ใบเสร็จ **ซ่อนแถวที่อยู่** เมื่อค่ายังตรงกับข้อความตั้งต้นพอดี ลูกค้าจึงไม่เห็นประโยค
ที่เขียนไว้คุยกันเองภายในร้าน — ข้อความตั้งต้นมาจาก `getDefaultMarketplaceShippingAddress()`
ที่เดียว ทั้งฟอร์มและใบเสร็จอ้างค่านี้ร่วมกัน และมี unit test ล็อกไว้ว่าสองฝั่งต้องไม่หลุดจากกัน

## ไฟล์หลัก

| ไฟล์ | หน้าที่ |
|---|---|
| `lib/marketplace/config.ts` | config ต่อช่องทาง (slug, prefix, ป้าย) + รายการค่าธรรมเนียม/ปรับปรุง |
| `lib/marketplace/settlement-math.ts` | สูตรกระทบยอด + การปันตามสัดส่วน (pure, มี unit test) |
| `lib/marketplace/queries.ts` | query ของหน้ากระทบยอดและรายงาน |
| `app/admin/(protected)/sales/_marketplace/` | server actions + หน้า/คอมโพเนนต์ที่ใช้ร่วมทุกช่องทาง |
| `app/admin/(protected)/sales/{shopee,lazada}/` | route wrapper บาง ๆ ต่อช่องทาง |
| `app/admin/(protected)/marketplace/settlements/[id]/` | หน้ารายละเอียดรอบรับเงิน (ใช้ร่วมทุกช่องทาง) |
| `app/admin/(protected)/reports/marketplace/` | รายงานผู้บริหารเทียบช่องทาง |

## ตั้งค่าก่อนใช้งานจริง

1. สร้าง `CashBankAccount` บัญชีพักเงิน **แยกใบต่อช่องทาง** — ระบบบล็อกไม่ให้สองช่องทางใช้บัญชีเดียวกัน
2. เตรียมลูกค้าเริ่มต้นของแต่ละช่องทาง
3. เข้าหน้า settlements ของช่องทางนั้นแล้วบันทึกการตั้งค่าครั้งแรก
4. สิทธิ์ที่ต้องมีสำหรับผู้กระทบยอด: `marketplace.manage`, `expenses.create/cancel`,
   `cash_bank.transfers.create/cancel`, `cash_bank.adjustments.create/cancel`
