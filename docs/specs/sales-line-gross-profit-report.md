# รายงานกำไรขั้นต้นรายบิล–รายสินค้า

สถานะ: Implemented และตรวจสอบแล้ว (2026-09-20)

## เป้าหมาย

สร้างรายงานระดับหนึ่งแถวต่อเอกสารและรายการสินค้า เพื่อให้ตรวจสอบได้ว่า
ราคาขายก่อนส่วนลด หักส่วนลดระดับรายการ หักส่วนลดท้ายบิลที่ปันกลับ แล้วเหลือ
รายได้เท่าใดเมื่อเทียบกับต้นทุน snapshot และกำไรขั้นต้นของรายการนั้น

## เส้นทางและสิทธิ์

- Route: `/admin/reports/sales-line-profit`
- ใช้ permission `reports.view` และ route guard `/admin/reports` ที่มีอยู่
- เพิ่มทางเข้าจากหน้ารายงานขาย ไม่เพิ่ม permission หรือ top-level admin menu ใหม่
- ใช้ `AdminSearchForm` + `AdminSearchSubmitButton` และ `AdminExportLink`

## ตัวกรอง

- ช่วงวันที่เอกสาร From–To (บังคับ)
- ลูกค้า: ค้นหาและเลือกได้หลายราย
- ช่องทาง: ทั้งหมด / หน้าร้าน / Shopee / Lazada
- หมวดสินค้า
- รหัสสินค้า From–To
- ค้นหาและเลือกสินค้าเฉพาะรายการได้หลายสินค้า
- สถานะเอกสาร: Active เป็นค่าเริ่มต้น และเลือกดู Cancelled เพื่อ audit ได้
- ใบลดหนี้/คืนสินค้า: รวมเป็นแถวติดลบโดยค่าเริ่มต้น และมีตัวเลือกซ่อน

เมื่อระบุหลายเงื่อนไขสินค้า ให้ใช้แบบ AND: อยู่ในหมวดที่เลือก อยู่ในช่วงรหัส และ
ถ้ามีรายการสินค้าที่เลือก ต้องเป็นหนึ่งในรายการนั้น

## คอลัมน์

- วันที่, ประเภทเอกสาร, เลขที่เอกสาร, เลขที่บิลขายต้นทาง
- ลูกค้า, ช่องทาง
- รหัสสินค้า, ชื่อสินค้า, จำนวน, หน่วย
- ราคาตั้งต่อหน่วย (`unitListPrice`)
- ยอดก่อนส่วนลด = ราคาตั้ง × จำนวนแสดง
- ส่วนลดระดับรายการ (`lineDiscount`)
- ยอดหลังส่วนลดรายการ (`SaleItem.totalAmount`)
- ส่วนลดท้ายบิลที่ปันกลับ = ยอดหลังส่วนลดรายการ − `FactProfit.salesAmountIncVat`
- ยอดขายสุทธิรวม VAT / ไม่รวม VAT
- ต้นทุน snapshot (`FactProfit.costAmount`)
- กำไรขั้นต้น (`FactProfit.grossProfit`) และ GP%

ใบลดหนี้แสดงจำนวน รายได้ ต้นทุน และกำไรเป็นค่าติดลบจาก `FactProfit` ชนิด
`SALE_RETURN`; ช่องราคาตั้งและส่วนลดที่ไม่มี snapshot ที่พิสูจน์ได้ให้แสดง `—`
แทนการเดาจากข้อมูลปัจจุบัน

## แหล่งข้อมูลและสูตร

- ใช้ `FactProfit` เป็น source of truth ของรายได้หลังปันส่วนลด ต้นทุน และกำไร
- Join `FactProfit.sourceLineId` กับ `SaleItem.id` สำหรับข้อมูลราคาตั้ง/ส่วนลดรายการ
- ส่วนลดท้ายบิลใช้ allocation เดียวกับ `rebuildSaleProfitFacts()` ซึ่งปัน
  `Sale.discount` ตามสัดส่วน `SaleItem.totalAmount` และเก็บผลหลังปันไว้ใน
  `FactProfit.salesAmountIncVat`
- Shipping เป็นแถวแยกใน FactProfit แต่ไม่ใช่สินค้า จึงไม่แสดงในตารางสินค้า;
  แสดงยอด shipping แยกใน subtotal ระดับบิลเพื่อให้ยอดรวมตรวจกลับกับบิลได้
- ทุกยอดเงินปัดสองตำแหน่ง และ subtotal ระดับบิลต้อง reconcile กับ FactProfit

## รูปแบบหน้าจอ

- Desktop: ตารางแบบ sticky header, subtotal ต่อบิล และ grand total ท้ายรายงาน
- Mobile: card ต่อรายการ โดยหัว card แสดงเลขบิล/สินค้า และพับรายละเอียดตัวเลขได้
- แถบสรุปด้านบน: ยอดก่อนส่วนลด, ส่วนลดรายการ, ส่วนลดท้ายบิล, ยอดขายสุทธิ,
  ต้นทุน, กำไรขั้นต้น และ GP%
- ลิงก์เลขเอกสารเปิดหน้าบิลหรือใบลดหนี้ต้นทาง
- Export Excel ใช้ชุด filter และสูตรเดียวกับหน้าจอ พร้อมแถว subtotal ต่อบิล

## แผน implementation

1. เพิ่ม query แบบ cursor/page limit โดยกรองวันที่ก่อน แล้ว filter ลูกค้า/สินค้าใน DB
2. สร้างตัวแปลง Sale และ SALE_RETURN เป็น row contract เดียวกัน
3. เพิ่ม assertion ตรวจยอดรวมรายบิลกับ FactProfit และกรณีเศษสตางค์จาก allocation
4. สร้างหน้า responsive พร้อม shared search/export components และ light/dark mode
5. เพิ่ม Excel export และป้องกัน prefetch ด้วย `AdminExportLink`
6. เพิ่ม integration tests: ส่วนลดรายการ, ส่วนลดท้ายบิลหลายสินค้า, VAT,
   สินค้าซ้ำในบิล, ใบลดหนี้ติดลบ, filter ทุกแบบ และ export parity
7. ตรวจ query plan บน production แบบ read-only ก่อนเปิดใช้ และรัน `npm run verify`,
   `npm run check:mojibake`, `npm run build`

## Acceptance criteria

- ผลรวมยอดขายสุทธิ/ต้นทุน/กำไรของแต่ละบิลตรง FactProfit ภายใน 0.01 บาท
- ส่วนลดท้ายบิลถูกปันด้วยสูตรเดียวกับตอนเขียน FactProfit ไม่คำนวณคนละสูตรใน UI
- ใบลดหนี้กลับเครื่องหมายรายได้ ต้นทุน และกำไรครบ
- ตัวกรองหน้าจอและไฟล์ Excel คืนชุดข้อมูลเดียวกัน
- รายงานใช้งานได้ทั้งมือถือและ desktop ใน light/dark mode

## ผลการ implementation

- มิติ “กำไรต่อบิล” รวมสินค้าทุกบรรทัดและค่าจัดส่งเพื่อให้ตรวจกลับกับ `FactProfit` ได้ ส่วนมิติ “กำไรต่อสินค้าในบิล” ใช้หมวดสินค้า ช่วงรหัส และรายการสินค้าที่เลือกแบบ AND
- สถานะ Active อ่าน current fact; สถานะ Cancelled อ่าน snapshot เวอร์ชันล่าสุดที่ถูก deactivate ตอนยกเลิก จึงไม่ปนกับเวอร์ชันเก่าจากการแก้ไขเอกสาร
- แถบสรุปแสดงยอดก่อนส่วนลด ส่วนลดรายการ ยอดหลังส่วนลด ส่วนลดท้ายบิลที่ปัน ค่าจัดส่ง ยอดสุทธิ ต้นทุน กำไร และ GP%; ถ้าเกิน 10,000 รายการ ช่อง breakdown ที่ต้อง join รายการขายจะแสดง `—` และให้กรองช่วงแคบลง
- Excel มี 2 sheet คือกำไรต่อบิลและกำไรต่อสินค้า ใช้ query/filter contract เดียวกับหน้าจอ และ export ผ่าน `AdminExportLink` พร้อม audit log
- Export Egress guard: preflight นับรายการสินค้าก่อนดึงรายละเอียด, ตอบ 422 โดยไม่สร้างไฟล์เมื่อเกิน 10,000 รายการ, ใช้ `limit + 1` ตรวจ scope ที่ถูกตัด, และใช้ export mode ที่ไม่เรียก aggregate/KPI/full-bill breakdown ของหน้าจอ จึงไม่ดึง FactProfit ซ้ำโดยไม่จำเป็น
- Production read-only smoke (2026-09-21, ช่วง 2026-09-01–2026-09-30): export mode ได้ 53 บิล/108 รายการใน 857 ms และไม่ถูก truncate
- ตรวจด้วย integration tests สำหรับบิลหลายสินค้า, VAT, ส่วนลดระดับรายการ/ท้ายบิล, product filter สองมิติ และใบคืนสินค้าติดลบ; `npm run verify` ผ่าน 986 tests และ `npm run build` ผ่าน
